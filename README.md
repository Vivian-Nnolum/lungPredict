# LungPredict — Lung Cancer Risk Prediction API

A machine learning system that estimates a person's lung cancer risk from a short
symptom/lifestyle questionnaire. It trains an XGBoost classifier on survey data,
saves the trained model, and serves predictions through a FastAPI endpoint that a
web or mobile front end can call.

## How it works

The project has three main parts that work together:

### 1. `survey lung cancer.csv` — training data
The raw dataset used to train the model. Each row is one survey respondent with:
- Demographics: `GENDER`, `AGE`
- Yes/No lifestyle & symptom fields (encoded as `1` = No, `2` = Yes in the raw
  file): `SMOKING`, `YELLOW_FINGERS`, `ANXIETY`, `PEER_PRESSURE`,
  `CHRONIC DISEASE`, `FATIGUE `, `ALLERGY `, `WHEEZING`, `ALCOHOL CONSUMING`,
  `COUGHING`, `SHORTNESS OF BREATH`, `SWALLOWING DIFFICULTY`, `CHEST PAIN`
- Target label: `LUNG_CANCER` (`YES`/`NO`)

### 2. `main.py` / `model.ipynb` — model training
This is where the model is built. The pipeline:
1. **Load & clean** — reads the CSV, drops duplicate rows.
2. **Encode** — `GENDER` and `LUNG_CANCER` are label-encoded to numbers;
   all Yes/No survey fields are remapped from the raw `1`/`2` scale to a
   standard `0`/`1` scale.
3. **Split** — 75/25 train/test split, stratified on the target so the class
   balance is preserved in both sets.
4. **Balance** — the training set is class-imbalanced (far more "No cancer"
   cases), so **SMOTE** oversampling is applied to the training split only,
   generating synthetic minority-class examples.
5. **Train (baseline)** — an `XGBClassifier` is fit with a fixed set of
   hyperparameters as a first pass, and evaluated for accuracy, recall, and
   precision.
6. **Tune** — a `RandomizedSearchCV` search (5-fold stratified CV, scored on
   average precision) explores a bounded hyperparameter space to find a
   stronger model without over-pruning trees.
7. **Save** — the best model from the search is serialized to `model.pkl`
   with `pickle`.

`model.ipynb` is the exploratory notebook version of this same process
(with data inspection and plotting); `main.py` is the clean, runnable script
version that produces `model.pkl`.

### 3. `app.py` — prediction API
A FastAPI application that loads `model.pkl` and exposes it over HTTP:

- **`GET /health`** — simple liveness check, returns `{"status": "ok"}`.
- **`POST /predict`** — accepts a JSON payload describing one patient
  (age, gender, and the same set of Yes/No questions as the training data,
  in camelCase field names), and returns:
  ```json
  { "risk_level": "High" | "Medium" | "Low", "probability": 73.2 }
  ```
  Internally it:
  1. Converts the incoming JSON into the exact column names, order, and
     encoding (`Yes`→`1`, `No`→`0`, `M`→`1`/`F`→`0`) the trained model
     expects — this must stay in sync with the encoding used in `main.py`.
  2. Loads `model.pkl` and runs `predict_proba` to get the probability of
     the positive (cancer) class.
  3. Buckets that probability into a risk level: **High** (≥60%),
     **Medium** (≥30%), **Low** (below 30%).

CORS is enabled so a separate front-end app (e.g. running on
`localhost:3000` or `127.0.0.1:5173`) can call the API directly from the
browser.

## Setup

1. Create and activate a virtual environment (recommended):
   ```bash
   python -m venv venv
   source venv/bin/activate   # Windows: venv\Scripts\activate
   ```
2. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```

## Usage

### Train the model (optional — `model.pkl` is already included)
```bash
python main.py
```
This re-reads `survey lung cancer.csv`, retrains, and overwrites `model.pkl`.
Print output includes accuracy/recall/precision for both the baseline and
tuned models, plus the best hyperparameters found.

### Run the API
```bash
python app.py
```
This starts the server at `http://127.0.0.1:8000` with hot reload enabled.
Equivalently:
```bash
uvicorn app:app --host 127.0.0.1 --port 8000 --reload
```

### Example request
```bash
curl -X POST http://127.0.0.1:8000/predict \
  -H "Content-Type: application/json" \
  -d '{
        "age": 65,
        "gender": "M",
        "smoking": "Yes",
        "yellowFingers": "Yes",
        "anxiety": "No",
        "peerPressure": "No",
        "chronicDisease": "No",
        "fatigue": "Yes",
        "allergy": "No",
        "wheezing": "Yes",
        "alcoholConsuming": "No",
        "coughing": "Yes",
        "shortnessOfBreath": "Yes",
        "swallowingDifficulty": "No",
        "chestPain": "Yes"
      }'
```

## Notes
- The Yes/No encoding used by `app.py`'s `preprocess_patient_input` must
  match the encoding used during training in `main.py`. An earlier version
  of `app.py` sent the raw `1`/`2` Kaggle scale straight to the model,
  which caused every "No" answer to be misread as a trained "Yes" — the
  current version encodes `Yes`→`1`/`No`→`0` to match training.
- This tool is for educational/demonstration purposes only and is **not** a
  medical diagnostic device.
